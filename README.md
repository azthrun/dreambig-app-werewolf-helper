# 狼人杀法官助手

供线下狼人杀法官（上帝）带场使用的手机网页工具。纯静态、无后端、无构建步骤，托管于 GitHub Pages。

**完整技术规格见 [SPEC.md](SPEC.md)。**

## 功能

- 6–20 人局型配置，19 个角色，9 人 / 12 人预设
- 夜晚流程引导，顺序可拖拽自定义
- **天亮结算推算** —— 守卫、解药、毒药、殉情、魅惑连锁自动推演并给出理由
- **死亡触发队列** —— 猎人 / 狼王开枪按死因判定资格，连锁逐条提示
- **信息角色直接给出答案** —— 预言家阵营、通灵师身份、守墓人查验、女巫看刀、熊咆哮判定
- 技能消耗追踪（女巫双药、守卫连守、一次性技能）
- 自由计时 + 发言计时（自动跳过阵亡座位）
- 局内日志按「第 N 夜 / 第 N 天」分组浏览，可筛选、可导出
- 姓名池跨局留存，一键沿用上次名单
- 每日随机首发言（座位 + 方向）
- 离线可用，可添加到主屏幕

## 设计原则

**辅助型，而非裁决型。** 应用提示但绝不阻断 —— 所有推算结论都是建议，法官可覆盖任何结果。狼人杀房规因桌而异，硬编码单一规则集的应用会在大量牌桌上出错并与法官对抗。真正改变死亡结果的少数规则分歧被提炼为 4 个设置开关，其余交由法官人工裁定。

**无弹窗。** 不使用模态框、遮罩、原生 `alert`/`confirm`。破坏性操作经长按守护（600ms + 进度反馈），其余操作「先执行 + 撤销条」。

**局内尽量不滚动。** ≤12 人零滚动保证；顶部控制区与步骤区始终固定，仅玩家网格可滚动。

## 已知限制

- **微震动在 iOS 上不可用** —— Safari 从未实现 Vibration API，无网页侧变通方案。警报以视觉为主（常驻横幅 + 卡片高亮脉冲），震动仅作为 Android 上的渐进增强。
- 13–20 人时玩家网格需要滚动。
- 魔术师与机械狼的语义细节交由法官人工裁定，引擎不做完整推演。
- 无自动胜负判定 —— 应用显示阵营计数，胜负由法官宣告。
- 单槽存档：开始新局即覆盖上一局。战报页的「复制日志文本」是唯一留存途径。
- v1 不含警长、投票计票、私密查看身份（架构已预留，见 SPEC §20）。

## 隐私

所有数据（玩家姓名、对局记录）仅存于本机浏览器 `localStorage`，**永不离开设备**。无后端、无分析、无网络请求。设置页提供「清空已存姓名」。

## 开发

无依赖、无构建步骤。任意静态服务器即可：

```bash
python3 -m http.server 8000
```

引擎测试打开 `test.html`。

## 部署

推送到 public 仓库，在 Settings → Pages 选择分支即可。注意：

- 全部路径必须为**相对路径**（`./app.js`），否则项目站点子路径下 Service Worker 注册失败
- 每次发布须递增 `sw.js` 中的 `CACHE_NAME`，否则用户会被钉在旧版本
- GitHub Pages 静态资源缓存约 10 分钟，重新部署后需等待传播

## 项目结构

```
index.html      页面骨架
style.css       设计令牌 + 组件层 + 布局
app.js          状态容器、渲染、手势、副作用
engine.js       纯函数：天亮结算、触发链、信息计算
roles.js        19 个角色与夜晚步骤的声明式数据表
storage.js      localStorage、版本化、姓名池
icons.svg       角色图标 sprite
manifest.json   PWA 清单
sw.js           Service Worker
test.html       engine.js 断言测试
SPEC.md         技术规格说明书
```
